# معماری AI-native

ارائهٔ درس معماری نرم‌افزار (کارشناسی ارشد). سه بخش جدا، که آخر کار در یک فایل پاورپوینت یکی می‌شوند. زمان‌بندی بخش سوم: ۱۲ دقیقه اسلاید و ۸ دقیقه بخش عملی.

تا وقتی هر سه نفر اسلاید بخش خودشان را تمام کنند، فایل یکپارچه ساخته نمی‌شود. اسکریپت ادغام آماده است و فقط وقتی گفته شود اجرا می‌شود.

## ارائه‌دهندگان

| بخش | پوشه | موضوع |
|-----|------|--------|
| ۱ | `part-01_foundations/` | مبانی و معماری مرجع |
| ۲ | `part-02/` | الگوهای معماری و تصمیم‌های طراحی |
| ۳ | `part-03_control-quality/` | کنترل، کیفیت، امنیت و تکامل + بخش عملی |

بخش سوم را متین قنبری ارائه می‌دهد. اسلاید جاری: `part-03_control-quality/slides/part-03_v4.pptx`.

## اجرای هر دو دمو با یک دستور (موقع ارائه)

از ریشهٔ مخزن:

```bash
python run_all.py
```

هر دو دمو بالا می‌آیند و صفحهٔ شروع در مرورگر باز می‌شود: http://127.0.0.1:8700

صفحهٔ شروع دو کارت دارد: «بخش ۱ و ۲» و «بخش ۳ — متین». هر دمو در زبانهٔ جدید باز می‌شود و ظاهرش هیچ تغییری نکرده است. برای برگشتن، زبانهٔ صفحهٔ شروع را انتخاب کنید. توقف همه: `Ctrl+C` در همان ترمینال.

| سرویس | پورت | توضیح |
|-------|------|-------|
| صفحهٔ شروع | 8700 | `launcher/home.html`، فقط stdlib |
| دموی بخش ۳ | 8765 | `demo/run_ui.py` |
| backend بخش ۱ و ۲ | 8000 | FastAPI/uvicorn، با `.venv` خود submodule |
| frontend بخش ۱ و ۲ | 3000 | Next.js (`next dev`)؛ پورت ثابت است چون CORS در backend فقط 3000 را قبول می‌کند |

گزینه‌ها: `--no-browser`، `--only part3` یا `--only part12`، `--home-port`، `--part3-port`، `--api-port`. لاگ هر سرویس در `launcher/logs/` نوشته می‌شود (در git نیست). اگر دمویی از قبل روی پورت خودش در حال اجرا باشد، لانچر همان را استفاده می‌کند.

پیش‌نیازها: Python 3، Node.js، و یک بار نصب وابستگی‌های submodule (`backend/.venv` و `frontend/node_modules`، طبق `part-01-02_demo/README.md`). بار اول، backend بخش ۱ و ۲ مدل embedding را بار می‌کند و ممکن است تا یک دقیقه طول بکشد. تا وقتی آماده نشده، دکمهٔ آن کارت غیرفعال است.

## اجرای دموی بخش ۳

```bash
cd demo
python run_ui.py
```

آدرس پیش‌فرض: http://127.0.0.1:8765

به اینترنت نیاز نیست (حالت آفلاین). با کلیدهای جهت‌نما بین مرحله‌ها جابه‌جا شوید. جزئیات در `demo/README_UI.md` و `demo/README.md`.

فونت AradFDVF تجاری است و در این مخزن نیست. اگر روی سیستم نصب باشد، یا فایل `AradFDVF.ttf` را در `demo/ui/fonts/` بگذارید، دمو از آن استفاده می‌کند؛ وگرنه Vazirmatn جایگزین می‌شود. راهنما: `demo/ui/fonts/README.md`.

## ادغام اسلایدها

از ریشهٔ مخزن:

```bash
python tools/merge_decks.py
```

خروجی: `dist/AI-native-Architecture.pptx`

چیدمان پیش‌فرض ادغام: عنوان (`front.pptx`) + بخش ۱ + بخش ۲ + بخش ۳ + منابع (`references.pptx`) + تشکر (`back.pptx`). اگر `references.pptx` موجود باشد، اسلایدهای «منابع این بخش» از فایل بخش ۳ در خروجی ادغام نمی‌آیند تا منابع دو بار تکرار نشوند. برای فقط سه بخش:

```bash
python tools/merge_decks.py --parts-only
```

چیدمان، یادداشت و انیمیشن هر اسلاید تا جایی که قالب اجازه بدهد حفظ می‌شود. شمارهٔ ترتیبی پاورپوینت از اول فایل یکپارچه می‌شود. اگر داخل خود اسلاید شمارهٔ ثابتی نوشته شده، آن را خود ارائه‌دهنده باید به‌روز کند.

وابستگی: Python 3 با بسته‌های `lxml` (برای ادغام) و در صورت بازسازی اسلاید بخش ۳، `python-pptx`.

فایل‌های پاورپوینت، ورد، تصویر و فونت به‌صورت باینری مشخص شده‌اند (`.gitattributes`). اگر بعداً فایل‌های خیلی بزرگ اضافه شد، می‌شود Git LFS را اختیاری راه انداخت؛ الان لازم نیست.
