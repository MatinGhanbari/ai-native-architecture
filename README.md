# معماری AI-native

ارائهٔ درس معماری نرم‌افزار (کارشناسی ارشد). سه بخش جدا، که آخر کار در یک فایل پاورپوینت یکی می‌شوند. زمان‌بندی بخش سوم: ۱۲ دقیقه اسلاید و ۸ دقیقه بخش عملی.

تا وقتی هر سه نفر اسلاید بخش خودشان را تمام کنند، فایل یکپارچه ساخته نمی‌شود. اسکریپت ادغام آماده است و فقط وقتی گفته شود اجرا می‌شود.

## ارائه‌دهندگان

| بخش | پوشه | موضوع |
|-----|------|--------|
| ۱ | `part-01/` | ساختار و معماری مرجع |
| ۲ | `part-02/` | الگوهای معماری و تصمیم‌های طراحی |
| ۳ | `part-03/` | چالش‌ها، کیفیت، امنیت و هزینه + بخش عملی |

بخش سوم را متین قنبری ارائه می‌دهد. اسلاید جاری: `part-03/slides/part-03_v7.pptx`.

## اجرای هر دو دمو با یک دستور (موقع ارائه)

از ریشهٔ مخزن:

```bash
python run_all.py
```

هر دو دمو بالا می‌آیند و صفحهٔ شروع در مرورگر باز می‌شود: http://127.0.0.1:8080

صفحهٔ شروع سه کارت دارد: «بخش اول — معماری C4» (فایل محلی `part-01/demo/c4-explorer.html`، `http://127.0.0.1:8080/part1/c4-explorer.html`؛ بدون سرور جدا و همیشه آماده)، «بخش دوم» (مسیر اجرای دستیار، `http://127.0.0.1:8082/`، و دکمهٔ «نمودار معماری» برای `http://127.0.0.1:8082/architecture`) و «بخش سوم». روی کارت‌ها اسم ارائه‌دهنده نیست. هر دمو در زبانهٔ جدید باز می‌شود و ظاهرش هیچ تغییری نکرده است. برای برگشتن، زبانهٔ صفحهٔ شروع را انتخاب کنید. توقف همه: `Ctrl+C` در همان ترمینال.

| سرویس | پورت | توضیح |
|-------|------|-------|
| صفحهٔ شروع + دموی بخش ۱ | 8080 | `launcher/home.html`، فقط stdlib؛ بخش ۱ روی `/part1/c4-explorer.html` |
| دموی بخش ۳ | 8084 | `demo/run_ui.py` |
| backend بخش ۲ | 8083 | FastAPI/uvicorn، با `.venv` خود submodule؛ از راه `launcher/part2_api.py` (mock پشتیبان) |
| پراکسی LLM بخش ۲ | 8085 | فقط در حالت 9router یا lmstudio؛ `launcher/llm_proxy.py` |
| frontend بخش ۲ | 8082 | Next.js (`next dev`، حالت webpack تا فونت‌ها از دیسک خوانده شوند)؛ CORS این پورت را `launcher/part2_api.py` به backend اضافه می‌کند |

گزینه‌ها: `--llm offline|9router|lmstudio`، `--no-browser`، `--only part3` یا `--only part2` (نام قدیمی `part12` هم کار می‌کند)، `--embeddings auto|local|mock`، `--home-port`، `--web-port`، `--api-port`، `--part3-port`، `--proxy-port` (همهٔ پیش‌فرض‌ها در بازهٔ 8080 تا 8090). لاگ هر سرویس در `launcher/logs/` نوشته می‌شود (در git نیست). اگر دمویی از قبل روی پورت خودش در حال اجرا باشد، لانچر همان را استفاده می‌کند.

پیش‌نیازها: Python 3، Node.js، و یک بار نصب وابستگی‌های submodule (`backend/.venv` و `frontend/node_modules`، طبق `part-02/demo/README.md`). بار اول، backend بخش ۲ مدل embedding را بار می‌کند و ممکن است تا یک دقیقه طول بکشد. تا وقتی آماده نشده، دکمهٔ آن کارت غیرفعال است.

## انتخاب مدل: آفلاین، 9router یا LM Studio

هر دو دمو سه حالت دارند:

| حالت | چه چیزی | پیش‌نیاز |
|------|---------|----------|
| `offline` (پیش‌فرض) | mock قطعی؛ بدون اینترنت و کلید. عددهای ارائه از همین حالت‌اند. | هیچ |
| `9router` | combo `demo` روی `http://localhost:20128/v1` | 9router روشن باشد |
| `lmstudio` | `qwen/qwen3-4b` روی `http://127.0.0.1:1234/v1` | LM Studio با سرور روشن و مدل بارشده |

کلیدها فقط در فایل `.env` ریشهٔ مخزن هستند و این فایل در git نیست. یک بار `.env.example` را به `.env` کپی کنید و کلیدها را بنویسید. `LLM_PROFILE` در همان فایل حالت پیش‌فرض را تعیین می‌کند.

```bash
python run_all.py                 # حالت پیش‌فرض از LLM_PROFILE در .env
python run_all.py --llm 9router
python run_all.py --llm lmstudio
python run_all.py --llm offline
```

- **دموی بخش ۳:** حالت را در خود صفحه هم می‌شود عوض کرد، با سوییچ سه‌حالتهٔ بالای صفحه: آفلاین / 9router / LM Studio. `--llm` فقط حالت اول صفحه را تعیین می‌کند.
- **دموی بخش ۲:** حالت موقع اجرا تعیین می‌شود. لانچر آن را با متغیرهای محیطی (`LLM_PROVIDER`، `LLM_BASE_URL`، `LLM_MODEL`) به backend می‌دهد و هیچ فایلی داخل submodule عوض نمی‌شود. در حالت زنده، backend به یک پراکسی کوچک در لانچر وصل می‌شود (`launcher/llm_proxy.py`، پورت 8085). کلید واقعی فقط دست پراکسی است. پراکسی `<think>` مدل Qwen3 را حذف می‌کند و embedding را محلی نگه می‌دارد تا نتیجهٔ بازیابی در هر سه حالت یکسان بماند.
- **سرویس خاموش:** اگر 9router یا LM Studio خاموش باشد، لانچر هشدار می‌دهد. دموی بخش ۲ خودش به mock برمی‌گردد و این را در badge صفحه نشان می‌دهد. دموی بخش ۳ خطای روشن نشان می‌دهد؛ در آن صورت سوییچ را روی آفلاین بگذارید.

## ادغام اسلایدها

از ریشهٔ مخزن:

```bash
python tools/merge_decks.py
```

خروجی: `dist/AI-native-Architecture.pptx`

چیدمان پیش‌فرض ادغام: عنوان (`front.pptx`) + بخش ۱ + بخش ۲ + بخش ۳ + یک صفحهٔ منابع نهایی (`references_selected.pptx`) + تشکر (`back.pptx`). اگر فایل منابع مشترک موجود باشد، اسلایدهای «منابع این بخش» از فایل هر بخش در خروجی ادغام نمی‌آیند. برای فقط سه بخش:

```bash
python tools/merge_decks.py --parts-only
```

چیدمان، یادداشت و انیمیشن هر اسلاید تا جایی که قالب اجازه بدهد حفظ می‌شود. شمارهٔ ترتیبی پاورپوینت از اول فایل یکپارچه می‌شود. اگر داخل خود اسلاید شمارهٔ ثابتی نوشته شده، آن را خود ارائه‌دهنده باید به‌روز کند.

وابستگی: Python 3 با بسته‌های `lxml` (برای ادغام) و در صورت بازسازی اسلاید بخش ۳، `python-pptx`.
