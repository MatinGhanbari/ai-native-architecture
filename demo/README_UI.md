# رابط وب بخش عملی (دمو نسخهٔ ۳)

یک صفحهٔ مرحله‌به‌مرحله برای بخش عملی ارائه (حدود ۷ دقیقه). همهٔ دکمه‌ها همان کد واقعی `assistant/` و `evals/` را اجرا می‌کنند؛ CLI قبلی (`run.py` و `evals/run_evals.py`) بدون تغییر کار می‌کند.

## اجرا در ویندوز
1. Python 3.9 یا بالاتر نصب باشد (هیچ کتابخانهٔ بیرونی و اینترنت لازم نیست).
2. پوشه را از zip بیرون بیاورید، در همین پوشه PowerShell باز کنید و بزنید:
```
python run_ui.py
```
مرورگر خودکار روی `http://127.0.0.1:8765/` باز می‌شود. توقف: `Ctrl+C`.
اگر درگاه اشغال بود: `$env:UI_PORT="8800"; python run_ui.py`

## حالت مدل: آفلاین / 9router / LM Studio
سوییچ بالای صفحه سه حالت دارد. «آفلاین» مدل ساختگی قطعی است. «9router» و «LM Studio» مدل واقعی‌اند و تنظیماتشان در `.env` ریشهٔ مخزن است (الگو: `.env.example`، در git نیست). حالت اول صفحه از `LLM_PROFILE` در `.env` یا گزینهٔ `--llm` لانچر می‌آید. اگر کلید یا تنظیم یک حالت کم باشد، وضعیت قرمز نمایش داده می‌شود و اجراها پیام خطای روشن می‌دهند. سر کلاس حالت آفلاین را پیشنهاد می‌کنم (قطعی و بدون اینترنت). حالت زنده کندتر است (هر اجرا چند ثانیه) و نتیجهٔ eval با مدل واقعی ممکن است با عددهای اسلاید فرق کند.

## کنترل‌ها
- «بعدی/قبلی» یا کلیدهای ← (بعدی) و → (قبلی)؛ Home/End برای اول و آخر. دایره‌های بالا مستقیم به هر مرحله می‌روند.
- دکمهٔ **reset**: حافظهٔ نشست و صف تأیید را پاک می‌کند (قبل از ارائه یک بار بزنید).
- پنل trace (سمت چپ): رویدادهای اجرا یکی‌یکی می‌آیند؛ مؤلفه‌های فعال معماری بالای آن روشن می‌شوند.
- نشانی مستقیم مرحله: `http://127.0.0.1:8765/#s=6`

## مراحل (ترتیب جدید، مسئله‌محور، حدود ۸ دقیقه)
صفحه از مرحلهٔ ۱ باز می‌شود. دایرهٔ «۰» نمای کلی معماری (اختیاری) است و دو دایرهٔ «+» در انتها مراحل اضافه‌اند.
| # | مرحله | چه چیزی دیده می‌شود |
|---|---|---|
| ۰ | نمای کلی (اختیاری) | نمودار مؤلفه‌ها |
| ۱ | حمله با سند آلوده | سند با کامنت HTML پنهان؛ guards خاموش → پاسخ لینک `sync.pakhsh…` با سفارش‌های همهٔ مشتریان می‌سازد |
| ۲ | همان حمله در سه پیکربندی | بدون دفاع (نشت) · فقط فیلتر (باز هم نشت) · دفاع ساختاری (egress allowlist لینک را حذف می‌کند) |
| ۳ | eval در CI | support-v3 = ۱۴/۱۴ (CI passed)؛ support-v4 = ۱۰/۱۴ (CI blocked). دکمهٔ «نتیجهٔ از پیش آماده» آخرین نتیجهٔ ذخیره‌شده را با برچسب precomputed نشان می‌دهد |
| ۴ | حلقهٔ بی‌پایان | state machine و نوار بودجهٔ گام تا STOPPED_BUDGET |
| ۵ | قطعی ارائه‌دهنده | (تیک از پیش زده است) timeout، retry، circuit breaker، fallback به مدل پشتیبان |
| ۶ | trace و هزینهٔ guards | trace کامل سفارش ۱۰۴۲ + جدول اندازه‌گیری‌شدهٔ تأخیر/token/هزینه/نشت برای سه سطح guard، با شرایط اندازه‌گیری (mock آفلاین) زیر جدول |
| + | تزریق مستقیم (اضافه) | guards خاموش در برابر روشن |
| + | صف تأیید انسانی (اضافه) | بازپرداخت در صف، تأیید/رد اپراتور |

**پشتیبان:** نتیجهٔ آخرین اجرای موفق هر دکمه در پوشهٔ `ui_cache/` ذخیره می‌شود (نتایج آفلاین از پیش در zip هست). اگر اجرای زنده خطا بدهد، همان نتیجه با برچسب «نتیجهٔ از پیش آماده (precomputed)» پخش می‌شود.
**صف تأیید و حافظهٔ نشست** با هر بار اجرای `run_ui.py` خودکار خالی می‌شوند (دکمهٔ reset هم هست).

نکته: در حالت آفلاین تأخیر با `MOCK_LATENCY_MS` شبیه‌سازی می‌شود و هزینه تقریبی است؛ اعداد برای نمایش سازوکارند. eval در UI با تأخیر کوتاه‌تر (`UI_EVAL_LATENCY_MS=30`) اجرا می‌شود تا منتظر نمانید.
